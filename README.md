# DocuScan

Android-приложение для съёмки документов. Оно фотографирует документ, само находит его границы, выравнивает перспективу и сохраняет результат в галерею (`Pictures/DocuScan`).

## Возможности

- **Камера с подсветкой документа.** Пока камера наведена на лист, его контур подсвечивается прямо в видоискателе.
- **Автоматическая обрезка.** После снимка границы документа находятся автоматически, в том числе для белого листа на белом столе. Углы можно поправить пальцем: при перетаскивании появляется лупа. Кнопка «Авто» возвращает найденные границы, «Весь кадр» выбирает всё фото.
- **Исправление перспективы.** Лист, снятый под углом, становится ровным прямоугольником. Реальное соотношение сторон восстанавливается по геометрии кадра, поэтому A4 остаётся A4, а не сплющивается.
- **Автоматический баланс белого.** Цвет бумаги определяется по самым светлым участкам и приводится к нейтральному белому, поэтому желтизна от ламп и серость пропадают.
- **Ручная настройка.** Ползунки «Температура» и «Оттенок» корректируют автоматический результат. Если выключить «Авто», они работают от исходных цветов снимка. Есть также яркость и контраст.
- **Три режима:** цветной, оттенки серого и чёрно-белый. В чёрно-белом режиме используется адаптивный порог, который справляется с тенями и неравномерным светом. Чувствительность настраивается ползунком «Порог».
- Поворот результата на 90°, импорт готового фото из галереи.
- Выбранный режим и настройка автобаланса запоминаются до следующего раза.
- Интерфейс на русском и английском языках.

## Как пользоваться

1. Наведите камеру на документ и нажмите кнопку съёмки (или выберите фото из галереи).
2. Проверьте границы и при необходимости перетащите углы. Нажмите «Далее».
3. Выберите режим, при желании подстройте баланс белого, яркость и контраст. Нажмите «Сохранить».

## Сборка

Нужны JDK 17+ и Android SDK (проще всего открыть проект в Android Studio).

```bash
./gradlew :core:test           # тесты обработки изображений (на JVM, с настоящим OpenCV)
./gradlew :app:assembleRelease # APK в app/build/outputs/apk/release/
./gradlew :app:assembleDebug   # отладочные APK в app/build/outputs/apk/debug/
```

Нативная библиотека OpenCV большая, поэтому собирается отдельный APK под каждый тип процессора:

| Файл | Для чего | Размер (release) |
| --- | --- | --- |
| `app-arm64-v8a-release.apk` | почти все современные телефоны | ~12 МБ |
| `app-armeabi-v7a-release.apk` | старые 32-битные телефоны | ~10 МБ |
| `app-x86_64-release.apk` | эмуляторы на x86 | ~27 МБ |
| `app-universal-release.apk` | подходит всем | ~45 МБ |

Release-сборка для удобства подписана debug-ключом, чтобы её можно было сразу установить. Перед публикацией подключите свой ключ в `app/build.gradle.kts`.

GitHub Actions (`.github/workflows/build.yml`) на каждый push запускает тесты и собирает оба APK. Скачать их можно в артефакте `DocuScan-apk` на странице запуска workflow.

Требования: Android 8.0 (API 26) и новее.

## Устройство проекта

| Модуль | Что внутри |
| --- | --- |
| `core` | Чистая обработка изображений на Kotlin + OpenCV, без зависимостей от Android: поиск документа (`DocumentDetector`), перспектива и пропорции (`Geometry.kt`), баланс белого, тоновая кривая и режимы (`Adjustments.kt`, `DocumentProcessor`). Покрыт юнит-тестами на синтетических «фотографиях». |
| `app` | Android-приложение на Jetpack Compose: камера (CameraX) и анализ кадров в реальном времени (`camera/DocumentAnalyzer`), экраны обрезки и настройки (`ui/`), загрузка и сохранение в галерею (`ImageIo`), состояние (`ScannerViewModel`). |

### Как работает обработка

1. **Поиск документа.** Кадр уменьшается до ~500 px, морфологическое замыкание стирает текст. Выпуклые четырёхугольники ищутся на нескольких картах: две карты границ Canny с фиксированными порогами, бинаризация Оцу и отдельный проход для белого листа на белом столе. В этом проходе локальный контраст выравнивается (CLAHE), а пороги Canny берутся из статистики градиентов самого кадра. Кандидат принимается, только если вдоль его сторон яркость действительно меняется поперёк стороны, причём в одну и ту же сторону по всей длине (по одну сторону бумага, по другую стол). Шум, фактура стола и края кадра так не выглядят. Из подходящих выбирается самый большой, близкие варианты усредняются.
2. **Выравнивание.** Соотношение сторон листа оценивается методом Zhang & He (2007): по четырём углам восстанавливается фокусное расстояние камеры. Затем выполняется `warpPerspective`.
3. **Баланс белого.** Средний цвет самых светлых 10 % пикселей считается цветом бумаги. Коэффициенты по каналам делают его белым (≈245). Ручные температура и оттенок умножаются сверху с сохранением яркости. Все коррекции цвета, яркости и контраста сводятся в одну таблицу (LUT), поэтому даже на полном разрешении обработка быстрая.
4. **Режимы.** Серый режим — это перевод в яркость. Чёрно-белый — адаптивный порог по среднему в окне примерно 1/16 размера страницы; крупные тёмные области при этом остаются чёрными.

Предпросмотр считается на уменьшенной копии (до 1600 px), а при сохранении та же обработка применяется к полному разрешению (до 4000 px по длинной стороне исходного фото).
